# TalkEcho v0.2.1

This release improves long-running meeting reliability and responsiveness. It replaces the fixed eight-item meeting queue with a coalescing two-stage pipeline, fixes conversation ordering, and removes increasingly expensive database and rendering work as a meeting grows.

## Highlights

- **No fixed queue overflow:** meeting audio no longer fails with `queue_full` after eight pending segments. Speech-to-text processing and AI generation now use one active batch plus one pending batch that absorbs newer segments in capture order.
- **Adaptive request coalescing:** transcription continues while the current AI response is being generated. New transcript text is appended to the single pending AI batch and sent together when the provider is ready, reducing duplicate request overhead while retaining the captured content.
- **Visible backlog estimate:** the meeting status now reports how many segments remain in the pipeline and an estimated catch-up time based on observed provider performance.
- **More stable long meetings:** conversation persistence writes only new or changed rows instead of deleting and reinserting the full message history after every response. Save requests arriving during an active write are retained and flushed afterward.
- **Lighter conversation rendering:** only the most recent 80 messages are rendered initially, with older messages available on demand. Memoized message rows avoid repeatedly rendering the full Markdown history during streaming responses.

## Correctness fixes

- Manual question history is now sorted by message timestamps, so each user question appears before its corresponding assistant answer.
- Manual prompts are excluded from automatic meeting-reference context.
- The `manual` message source is preserved when conversations are saved and reloaded.
- Stopping capture, closing the overlay, or starting a new conversation invalidates queued work so an old batch cannot write into the next meeting.
