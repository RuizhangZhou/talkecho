# TalkEcho v0.2.2

This release reduces avoidable meeting backlog and makes slow requests and errors easier to diagnose. It builds on v0.2.1's coalescing queue without allowing accumulated transcript text to grow into an unbounded translation request.

## Meeting latency and reliability

- Run at most two file-transcription requests concurrently, while committing results in capture order. A completed transcript can move to translation once earlier outcomes are known instead of waiting for an entire batch.
- Keep one pending translation buffer, but process bounded slices of at most eight parts / approximately 400 estimated tokens. Oversized utterances are split without dropping characters; the remaining text stays queued in order. Eight is a per-request limit, not a queue-capacity limit.
- Limit automatic meeting-reference context to approximately 400 estimated tokens, excluding the current and newer pending utterances. Custom system prompts are not truncated.
- Save recognized text to conversation history before translation. A failed translation no longer hides the successfully transcribed original.
- Propagate custom-provider cancellation to native HTTP and stop an abandoned stream before retrying. Reuse HTTP connections and honor Retry-After on translation retries.
- Preserve timeout classification when native response-body or stream reads fail.

## Diagnostics

- Catch-up estimates account for overlapping stages and transcript size. The status also shows the measured age of the oldest unfinished part, from receipt of its completed audio segment.
- Expand **Meeting diagnostics** to see recent transcription duration, AI first-text delay, AI total duration, and the last ten errors, even after the red status clears.
- **Copy diagnostics** includes recent structured events and the local log location. Rotating `meeting.log` files survive app closure and exclude audio, transcript text, prompts, credentials and provider response bodies.
- Errors identify the affected stage and category, including timeouts, rate limits and context-limit rejection.

## Validation and limits

- Automated coverage includes ordered concurrency, bounded batching, multilingual splitting, a virtual-clock 30-minute meeting, generated WAV uploads to a loopback provider, HTTP 429/503, stalled streams and cancellation races.
- Native tests verify actual local socket closure on cancellation and response-body timeout classification. Existing history, persistence, credential and shortcut tests remain included.
- Controlled simulation results are not a benchmark of a live provider. A provider whose sustained throughput is below incoming speech can still accumulate backlog; actual microphone/system-audio hardware and provider/model field validation remain necessary.
- Raw audio is not persisted after final transcription failure. Managed TalkEcho transcription retains its existing non-replayable invocation path; the new native HTTP cancellation applies to custom-provider requests.
- Windows unit-test manifest settings are isolated from the application's production manifest.

## Downloads and installation

- `TalkEcho_0.2.2_x64-setup.exe`: Windows x64 NSIS installer (recommended for normal installation).
- `TalkEcho_0.2.2_x64_en-US.msi`: Windows x64 MSI installer.
- `SHA256SUMS.txt`: SHA-256 checksums for both installers.

Close TalkEcho before installing. These Windows installers are not Authenticode-signed, so Windows may show an unknown-publisher warning. Updater signatures are not configured; download and install this release manually. This local build does not embed managed-service endpoints or compile-time service credentials; custom-provider configuration remains available. No macOS or Linux binaries are included in this release.
